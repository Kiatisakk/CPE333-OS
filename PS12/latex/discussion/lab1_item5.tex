Yes for a symbolic link or a junction, no for a hard link. A hard link names an
inode or MFT record, and those numbers only have meaning within one volume; a
symbolic link stores a path, which can point anywhere.

The test machine has only drive~\texttt{C:}, so \texttt{D:} was made with
\texttt{subst} as an alias of a folder on \texttt{C:}. Both letters are then the
same NTFS volume, which is why \texttt{mklink /H} succeeded here; across two
real volumes it is refused. The Linux run shows the real refusal: \texttt{/tmp}
and \texttt{/dev/shm} are separate filesystems, so \texttt{ln} fails with
\texttt{Invalid cross-device link} while \texttt{ln -s} works.
