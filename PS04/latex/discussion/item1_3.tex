Yes, the results differ, and the table shows exactly where.

By default \texttt{gcc} produces a \emph{position-independent executable}, which
the loader is free to place at a randomly chosen base address; every address
inside it shifts with that base, so the static \texttt{y} lands somewhere new on
every run. \texttt{-no-pie} produces a fixed-position executable instead, linked
to load at one address, so \texttt{y} is at \texttt{0x404018} in all three runs.
The \emph{values} 6, 7, 8 never change --- storage duration is a language rule
and has nothing to do with how the image is loaded.

The last row is the useful one: without \texttt{static}, the address still moves
between runs even under \texttt{-no-pie}. That variable is on the stack, and the
stack is randomised by address-space layout randomisation, which the kernel
applies independently of whether the executable is position-independent.
Turning off PIE fixes where the \emph{program} is loaded; it does not turn ASLR
off.
