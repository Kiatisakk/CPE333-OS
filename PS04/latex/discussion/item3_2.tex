The result does differ from the previous run: with \texttt{b} allocated,
\texttt{a} moves.

Allocating \texttt{b} immediately after \texttt{a} prevents in-place expansion
during \texttt{realloc(a, 1000 * sizeof(int))}. Because \texttt{b}'s chunk
obstructs contiguous growth, the allocator relocates \texttt{a} to a
sufficiently large free block, copies the existing contents, releases the old
block and returns a new address.

Whether a block moves is therefore not a property of the program but of what
else has been allocated around it: the \texttt{realloc} call is identical in
both versions. This is why its return value must always be reassigned to the
pointer, and why any other pointer into the old block is invalid afterwards.
